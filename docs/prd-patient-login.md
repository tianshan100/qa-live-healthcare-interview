# PRD: 问诊用户登录功能

## 1. 特性名称

问诊用户用户名密码登录（注册即登录）

## 2. 背景与动机

当前系统中问诊用户（患者）使用"姓名+生日"进行身份验证，存在以下问题：
- 无法保证身份唯一性，同名同生日可能冲突
- 缺乏密码保护，任何人知道姓名和生日即可冒用
- 与医生登录方式不一致，用户体验不统一

本特性将问诊用户的身份验证改为用户名+密码方式，并支持"注册即登录"——若用户名不存在则自动创建账号并登录。

## 3. 目标

1. 问诊用户通过用户名+密码进行登录
2. 新用户输入用户名+密码后自动注册并登录（无需单独注册流程）
3. 防止重复提交（防抖 500ms）
4. 完善异常提示（密码错误、网络异常、输入校验等）

## 4. 用户故事

- 作为问诊用户，我希望通过用户名和密码登录系统，以便安全地使用问诊服务
- 作为新问诊用户，我希望首次输入用户名和密码后自动完成注册并登录，以便快速开始问诊
- 作为问诊用户，我希望输入错误时有明确的提示信息，以便及时纠正

## 5. 功能需求

### 5.1 核心功能

1. **登录/自动注册**：用户输入用户名和密码，提交后：
   - 若用户名已存在且密码正确 -> 登录成功
   - 若用户名已存在但密码错误 -> 提示"用户名或密码错误"
   - 若用户名不存在 -> 自动创建账号并登录，提示"注册成功，已自动登录"

2. **防抖保护**：登录按钮点击后 500ms 内禁用重复点击

3. **输入校验**：
   - 用户名：3-20 位字母、数字、下划线、连字符，必填
   - 密码：6-20 位，必填

### 5.2 边界条件

- 用户名不区分大小写存储，登录时也忽略大小写（暂不实现，保持简单）
- 密码以明文存储（MVP 阶段，后续可升级加密）
- 自动注册的用户 name 字段默认等于 username

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 登录接口响应时间 < 500ms |
| 安全 | 防止重复提交；密码错误不提示具体是用户名还是密码错误 |
| 兼容性 | 支持主流浏览器，移动端适配 |
| 可用性 | 错误提示清晰，操作步骤最少化 |

## 7. 异常处理

| 异常场景 | 前端处理 | 后端处理 |
|----------|----------|----------|
| 用户名或密码为空 | 表单校验拦截，不提交 | @Valid 参数校验返回 400 |
| 用户名格式不合法 | 正则校验拦截 | 后端正则校验返回 400 |
| 用户名已存在但密码错误 | 提示"用户名或密码错误" | 返回 401 |
| 用户名不存在 | 提示"注册成功，已自动登录" | 自动创建返回 201 |
| 重复提交 | 按钮 loading + 500ms 防抖 | — |
| 网络异常 | catch 错误，提示"网络异常，请重试" | — |

## 8. 接口设计

### 8.1 API 列表

| 方法 | 路径 | 描述 |
|------|------|------|
| POST | /api/patients/login | 问诊用户登录（注册即登录） |

### 8.2 请求/响应示例

**POST /api/patients/login**

请求体：
```json
{
  "username": "patient-zhao",
  "password": "123456"
}
```

登录成功响应（200）：
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "id": "1",
    "username": "patient-zhao",
    "name": "patient-zhao",
    "phone": "",
    "gender": ""
  }
}
```

注册即登录响应（201）：
```json
{
  "code": 201,
  "message": "注册成功，已自动登录",
  "data": {
    "id": "6",
    "username": "new-user",
    "name": "new-user",
    "phone": "",
    "gender": ""
  }
}
```

密码错误响应（401）：
```json
{
  "code": 401,
  "message": "用户名或密码错误"
}
```

参数校验失败响应（400）：
```json
{
  "code": 400,
  "message": "用户名格式不正确"
}
```

## 9. 数据模型

| password | VARCHAR(100) | NOT NULL | 密码 |
| name | VARCHAR(50) | | 姓名 |

| gender | VARCHAR(10) | | 性别 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

## 10. 前端交互

1. 用户进入问诊页面（/consultation），若未登录则显示登录表单
2. 输入用户名和密码，点击"登录"按钮
3. 按钮进入 loading 状态，500ms 内禁止再次点击
4. 调用 POST /api/patients/login 接口
5. 成功后显示问诊主界面
6. 失败则显示对应错误提示
